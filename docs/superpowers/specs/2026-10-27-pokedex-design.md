# 포켓몬 도감 웹페이지 설계

작성일: 2026-10-27

## 의도와 이유

사용자가 **혼자 쓰는 개인용 포켓몬 도감**을 만들면서 **React를 배우는 것**이 목표다. HTML·CSS·JavaScript 기초는 어느 정도 알고 있다. 코드는 Claude가 쓰고, **단계마다 무엇을 왜 그렇게 썼는지 설명**한다. 사용자는 설명을 읽고 결과를 브라우저에서 확인하면서 따라온다.

따라서 결과물만큼이나 **코드가 읽고 따라가기 쉬운지**가 중요하다.

## 목표

- 1~9세대 포켓몬 전체(1,025종)를 한국어 이름으로 카드 목록에 보여 준다.
- 위쪽 검색창에서 이름으로 찾는다.
- 왼쪽 사이드바에서 세대별·타입별로 모아 본다.
- 카드를 누르면 상세 페이지로 이동해 기본 정보, 배틀 정보, 진화, 모습 바꾸기, 기술, 세부 데이터를 본다.
- 만드는 과정에서 React의 핵심 개념을 하나씩 익힌다.

## 하지 않는 것 (비목표)

- 배포, 로그인, 즐겨찾기, 파티 짜기 같은 부가 기능
- 이로치 이미지, 게임 도트 이미지, 울음소리 (사용자가 공식 일러스트만 선택함)
- TypeScript, Tailwind 등 추가로 배워야 하는 도구
- 모바일 전용 디자인 (PC 우선. 좁은 화면에서 깨지지 않는 정도만)

## 실패로 보는 것 (안티 목표)

- 기능은 되지만 초보자가 따라 읽을 수 없을 만큼 추상화되거나 복잡한 코드
- 한국어 데이터가 있는데도 영어 이름·설명이 노출되는 화면
- 첫 화면이 뜨는 데 오래 걸려서 쓰기 답답한 도감 (목록 로딩은 수 초 이내)
- 설명 없이 코드만 잔뜩 생기는 진행 방식

## 제약 조건

- 환경: Windows 11. **Node.js가 설치되어 있지 않다.** 개발을 시작하기 전에 Node.js LTS를 설치해야 한다 (예: `winget install OpenJS.NodeJS.LTS`).
- 작업 폴더 `C:\JUNWOO\ClaudeProject`는 비어 있고 git 저장소도 아니다.
- 데이터는 전부 **PokeAPI**(무료 공개 API)에서 가져온다. 별도 서버나 데이터베이스는 없다.
- PokeAPI REST의 전체 목록은 영어 이름만 준다. 한국어 이름은 종(species)마다 따로 요청해야 해서, REST만 쓰면 목록에 1,000번 넘는 요청이 필요하다.
  - **확인함 (2026-10-27):** GraphQL 엔드포인트 `https://graphql.pokeapi.co/v1beta2`에 요청 한 번을 보내면 1,025종 전체의 id, 세대, 한국어 이름, 기본 모습의 타입이 약 150KB 크기로 1초 안에 온다. 한국어 이름이 빠진 종은 없다.
  - 이 엔드포인트는 이름에 `beta`가 붙어 있다. 응답 형식이 바뀔 수 있으니, 데이터를 가져오는 코드는 한곳에 모아 둔다.

## 고려한 방법

| 방법 | 장점 | 단점 |
|---|---|---|
| A. HTML + CSS + JavaScript만 사용 | 설치가 필요 없다. 웹 기초를 직접 짜 보며 익힌다. | 화면 전환이 많은 상세 페이지는 코드가 길어진다. |
| **B. React + Vite (선택)** | 실무 표준 방식이다. 카드, 탭, 사이드바를 컴포넌트로 조립한다. | Node.js 설치가 필요하다. 개발 도구 사용법도 함께 배워야 한다. |
| C. Next.js | 기능이 많다. | 서버 기능이 핵심인 도구라 개인용 도감에는 과하다. 처음에 바로 뺐다. |

Claude는 A를 추천했다. 사용자는 HTML·CSS·JavaScript 기초를 이미 알고 있어서 **B를 선택했다.**

## 사용자가 정한 것

### 메인 화면 (시안 B: 왼쪽 사이드바)
- 맨 위 빨간 상단 바에 로고와 **이름 검색창**이 있다.
- 왼쪽 사이드바에 **세대 목록**(전체, 1세대(관동) … 9세대)과 **타입 목록**(전체, 노말, 불꽃 …)이 항상 펼쳐져 있다.
- 오른쪽에 포켓몬 **카드 그리드**가 있다. 카드에는 공식 일러스트, 도감 번호(#0006 형식), 한국어 이름, 타입 배지가 들어간다.
- 카드를 누르면 상세 페이지로 이동한다.

### 상세 페이지 (시안 B: 핵심 정보 + 탭)
- **항상 위에 보이는 영역:** 「← 도감으로 돌아가기」, 공식 일러스트, 번호, 이름, 분류(예: 화염포켓몬), 타입, 키·몸무게, 전설·환상 여부, 한국어 도감 설명
- **탭 4개:**
  1. **배틀:** 기본 능력치 6종(막대그래프 + 합계), 특성과 숨겨진 특성(한국어 설명 포함), 타입 상성(받는 피해 ×4, ×2, ×½, ×¼, ×0)
  2. **진화·모습:** 진화 단계와 조건(레벨, 아이템 등), 모습 바꾸기(메가진화, 지역 모습, 거다이맥스 등)
  3. **기술:** 배우는 기술 표(레벨/방법, 기술 이름, 타입, 위력, 명중)
  4. **세부 데이터:** 성비, 포획률, 알 그룹, 부화 걸음 수, 성장 속도, 서식지, 색깔, 게임별 출현 장소

시안 파일은 `.superpowers/brainstorm/mockups/layout.html`과 `detail.html`에 있다.

### 진행 방식
- Claude가 코드를 쓰고, **단계마다 설명한다.** 설명에는 이번 단계에서 새로 나온 React 개념, 코드가 하는 일, 브라우저에서 확인하는 방법이 들어간다.
- 단계는 React 개념이 하나씩 쌓이는 순서로 나눈다. 예를 들어 컴포넌트와 JSX → props → 상태(state) → 데이터 불러오기(effect) → 라우팅 → 검색·필터 같은 파생 데이터 → 커스텀 훅 순서다.
- 한 단계가 끝날 때마다 실제로 실행되는 상태여야 한다. 사용자가 브라우저에서 결과를 보고 다음 단계로 넘어간다.
- **복습용 학습 노트:** 단계마다 대화창 설명과 별도로 `docs/learning/` 폴더에 한국어 마크다운 파일을 남긴다 (예: `01-컴포넌트와-JSX.md`). 노트에는 이번 단계에서 배운 개념, 핵심 코드 조각과 설명, 직접 바꿔 볼 만한 연습 거리를 담는다. 나중에 참고서처럼 다시 읽을 수 있게 하기 위해서다.

## Claude가 정한 것 (사용자가 바꿀 수 있음)

- **언어와 도구:** JavaScript(TypeScript 아님), React + Vite, 페이지 이동은 React Router, 꾸미기는 일반 CSS 파일. 이유는 배울 거리를 React 하나에 집중하기 위해서다.
- **주소 구조:** 목록은 `/`, 상세는 `/pokemon/:id` (예: `/pokemon/6`)
- **필터 동작:** 세대와 타입은 각각 하나씩 고르고(기본값 「전체」), 검색어와 함께 **세 조건을 모두 만족하는** 포켓몬만 보여 준다. 타입이 두 개인 포켓몬은 둘 중 하나만 맞아도 해당 타입에 들어간다 (리자몽은 불꽃에도, 비행에도 나온다).
- **검색:** 한국어 이름의 일부만 입력해도 찾는다 (「리자」 → 리자드, 리자몽). 도감 번호 숫자로도 찾는다.
- **목록 데이터:** GraphQL 요청 한 번으로 받아서 브라우저(localStorage)에 저장해 둔다. 두 번째 방문부터는 바로 뜬다.
- **목록에는 종마다 기본 모습 하나만** 나온다. 메가진화나 지역 모습은 상세 페이지의 「진화·모습」 탭에서 본다.
- **모습 바꾸기:** 모습 카드를 누르면 위쪽 그림, 타입, 능력치, 특성이 그 모습 기준으로 바뀐다.
- **진화 단계의 포켓몬을 누르면** 그 포켓몬의 상세 페이지로 이동한다.
- **기술 탭과 출현 장소:** 게임 버전 선택 메뉴를 둔다. 기본값은 그 포켓몬 데이터가 있는 가장 최신 버전이다. 기술은 습득 방법(레벨업, 기술머신, 알, 가르침)도 고를 수 있다.
- **한국어가 없을 때:** 출현 장소 이름 등 한국어 번역이 없는 데이터는 영어로 보여 준다. 도감 설명은 한국어가 있는 문구 중 가장 최신 것을 쓴다.
- **정렬과 이미지:** 목록은 도감 번호 순서다. 카드 1,025장의 이미지는 화면에 보일 때 불러온다 (`loading="lazy"`).
- **화면 크기:** PC 우선이다. 좁은 화면에서는 사이드바가 그리드 위로 올라간다.
- **테스트:** 타입 상성 계산과 필터처럼 순수 계산 로직에만 Vitest로 간단한 테스트를 붙인다. 테스트도 학습 단계 중 하나로 소개한다.
- **git:** 작업 폴더에서 git을 시작하고 단계마다 커밋한다. 사용자가 단계별 변화를 되돌아볼 수 있게 하기 위해서다.

## 만드는 사람에게 맡기는 것

- 상세 페이지 데이터를 REST 여러 요청으로 받을지, GraphQL로 한 번에 받을지. 특히 기술 탭은 기술마다 한국어 이름·위력·명중이 필요해서, REST로 하면 포켓몬 하나에 요청이 100번 가까이 갈 수 있다.
- 타입 한국어 이름과 색, 세대 지역명을 코드에 고정할지, API에서 받을지
- 폴더 구조와 컴포넌트를 어떻게 나눌지 (단, 초보자가 따라 읽기 쉬운 수준을 유지한다)
- 로딩·오류 화면의 모양
- 단계를 구체적으로 몇 개로 나누고 각 단계에 무엇을 넣을지 (위 「진행 방식」의 순서 원칙을 따른다)
