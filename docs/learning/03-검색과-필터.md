# 03. 검색과 필터: 제어 컴포넌트, 상태 끌어올리기, 파생 데이터

## 이번 단계에서 한 일

- 상단 바에 **검색창**을 넣었다. 이름 일부나 도감 번호로 찾는다.
- 왼쪽에 **사이드바**를 만들었다. 세대와 타입을 하나씩 고른다.
- 세 조건을 **모두 만족하는** 포켓몬만 보여 주고, 위에 「N마리」 개수를 표시한다.
- 목록 화면 전체를 `src/pages/ListPage.jsx`로 옮겼다. `App`은 이제 화면을 고르는 역할만 한다. (다음 단계에서 상세 페이지가 생긴다)

```
ListPage                      ← query, generation, type 상태를 여기서 가짐
├─ Header
│   └─ <input>  검색창          value={query}, onChange → setQuery
├─ Sidebar                     generation, type을 받아 표시. 클릭하면 onGenerationChange/onTypeChange 호출
└─ PokemonGrid                 filterPokemon(list, 조건)의 결과만 받음
```

## 개념 1: 제어 컴포넌트(controlled component)

```jsx
const [query, setQuery] = useState('')

<input
  value={query}
  onChange={(event) => setQuery(event.target.value)}
/>
```

- `value={query}`: 입력창에 보이는 글자는 **항상 state 값**이다.
- `onChange`: 사용자가 타이핑하면 `event.target.value`(입력창의 새 글자)로 state를 바꾼다. state가 바뀌면 화면이 다시 그려지고, 입력창에도 새 글자가 보인다.
- 이렇게 "입력창의 값을 React state가 쥐고 있는" 방식을 **제어 컴포넌트**라고 한다. 그래서 검색어를 다른 곳(필터 함수)에서도 바로 쓸 수 있다.

## 개념 2: 상태 끌어올리기(lifting state up)

사이드바에서 고른 세대는 **사이드바가 아니라 부모인 `ListPage`가 가지고 있다.**

```jsx
// ListPage
const [generation, setGeneration] = useState(null)

<Sidebar
  generation={generation}              // 지금 값을 내려 줌
  onGenerationChange={setGeneration}   // 바꾸는 함수를 내려 줌
/>
```

```jsx
// Sidebar 안의 버튼
<button onClick={() => onChange(option.value)}>
```

왜 그럴까? **선택한 세대는 사이드바만 쓰는 값이 아니기 때문이다.** 그리드도 그 값으로 걸러야 한다. 형제 컴포넌트(Sidebar와 PokemonGrid)가 같은 값을 써야 하면, 그 값을 **공통 부모로 끌어올린다.** 그러면 데이터는 위에서 아래로(props), 변경 요청은 아래에서 위로(함수 호출) 흐른다.

```
        ListPage (generation)
        ↓ 값        ↑ onGenerationChange(2)
     Sidebar      PokemonGrid
```

## 개념 3: 파생 데이터와 useMemo

"걸러진 목록"은 state로 따로 만들지 않았다. **`list`와 조건들만 있으면 언제든 계산할 수 있기 때문**이다.

```js
const filtered = useMemo(
  () => filterPokemon(list, { query, generation, type }),
  [list, query, generation, type],
)
```

- 계산으로 얻을 수 있는 값을 state로 또 만들면, 원본이 바뀔 때 같이 바꾸는 걸 깜빡해서 둘이 어긋나기 쉽다. **state는 최소한으로, 나머지는 계산**하는 게 원칙이다.
- `useMemo`는 계산 결과를 기억해 두고, 배열 안의 값이 바뀔 때만 다시 계산한다. 1,025마리를 거르는 계산은 사실 금방 끝나서 `useMemo`가 없어도 괜찮지만, 이런 도구가 있다는 걸 익혀 두자.

## 개념 4: 거르는 규칙은 순수 함수로

`src/lib/filter.js`:
```js
export function filterPokemon(list, { query, generation, type }) {
  const keyword = query.trim()
  const isNumber = /^\d+$/.test(keyword)

  return list.filter((pokemon) => {
    if (generation !== null && pokemon.generation !== generation) return false
    if (type !== null && !pokemon.types.includes(type)) return false
    if (keyword === '') return true
    if (isNumber) return pokemon.id === Number(keyword)
    return pokemon.name.includes(keyword)
  })
}
```

- 조건을 하나씩 검사해서 안 맞으면 바로 `false`를 돌려준다(빠른 탈출). 모든 검사를 통과해야 남는다.
- `/^\d+$/`는 "처음부터 끝까지 숫자만"이라는 정규식이다. 숫자만 입력하면 도감 번호로 찾는다.
- `types.includes(type)`: 리자몽(불꽃/비행)은 「비행」을 골라도 나온다.
- React와 상관없는 함수라서 테스트하기 쉽다. 테스트 7개가 이 규칙을 지키고 있다.

## 개념 5: 「전체」는 null

`generation`과 `type`의 「전체」는 `null`로 표현했다. `null`이면 "거르지 않음"이다. 사이드바는 `[{ value: null, label: '전체' }, ...options]`처럼 맨 앞에 「전체」를 붙여서 그린다. `...`는 배열을 펼쳐서 이어 붙이는 문법이다.
