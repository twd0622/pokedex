# 05. 탭과 조건부 렌더링, 배틀 탭

## 이번 단계에서 한 일

- 상세 페이지 아래에 **탭 4개**(배틀 / 진화·모습 / 기술 / 세부 데이터)를 만들었다. 선택한 탭은 주소(`?tab=battle`)에 남는다.
- **배틀 탭**: 기본 능력치 막대와 합계, 특성(숨겨진 특성 표시), 받는 피해 배율표
- 나머지 탭 3개는 「준비 중」이다. 다음 단계들에서 하나씩 채운다.

```
DetailPage                    activeTab (주소 ?tab=)
├─ Hero
├─ Tabs                       tabs, active, onChange
└─ {activeTab === 'battle' && <BattleTab form={form} />}
     ├─ StatBars
     ├─ Abilities
     └─ TypeMatchup           ← getDefensiveMultipliers + groupByMultiplier
```

## 개념 1: 탭은 "선택된 id 하나"로 표현한다

탭 UI의 상태는 **어떤 탭이 선택됐는지** 하나뿐이다.

```jsx
const activeTab = TABS.some((t) => t.id === tabParam) ? tabParam : 'battle'

<Tabs tabs={TABS} active={activeTab} onChange={changeTab} />
{activeTab === 'battle' && <BattleTab form={form} />}
```

- `Tabs`는 버튼만 그린다. 누르면 `onChange('moves')`처럼 부모에게 알린다. 지난 단계의 사이드바와 같은 패턴이다(상태 끌어올리기).
- 탭 정보를 배열 `TABS`로 만들어 두고 `map`으로 버튼을 그린다. 탭을 하나 더 만들고 싶으면 배열에 한 줄만 추가하면 된다.
- 이번에도 선택한 탭을 주소에 두었다. 새로고침하거나 주소를 복사해도 같은 탭이 열린다.

## 개념 2: 조건부 렌더링 3가지 방법

| 쓰는 곳 | 방법 | 예 |
|---|---|---|
| 보이거나 안 보이거나 | `조건 && <JSX>` | `{ability.isHidden && <span>숨겨진 특성</span>}` |
| 둘 중 하나 | `조건 ? <A> : <B>` | `{filtered.length > 0 ? <Grid/> : <p>없어요</p>}` (3단계) |
| 함수 맨 앞에서 통째로 | `if (...) return ...` | `if (loading) return <p>불러오는 중…</p>` (4단계) |

### 빈 줄은 숨기기: `filter` 후 `map`
```jsx
{MULTIPLIER_ROWS.filter((row) => groups[row.value].length > 0).map((row) => ( ... ))}
```
리자몽처럼 ×4가 있는 포켓몬도 있고, 없는 포켓몬도 있다. **배열을 먼저 거르고(`filter`) 남은 것만 그리면(`map`)** 빈 줄이 생기지 않는다.

### 주의: `&&` 앞에 숫자를 두지 말자
```jsx
{count && <p>{count}마리</p>}   // count가 0이면 화면에 "0"이 찍힌다!
{count > 0 && <p>{count}마리</p>}  // 이렇게 비교식으로 쓰자
```

## 개념 3: 한 파일 안의 작은 컴포넌트

`BattleTab.jsx` 안에 `StatBars`, `Abilities`, `TypeMatchup`을 함께 두었다. 이 셋은 배틀 탭에서만 쓰기 때문이다. 여러 곳에서 쓰게 되면 그때 파일로 분리하면 된다.

### 인라인 스타일로 막대 길이 정하기
```jsx
<i style={{ width: `${(stats[key] / MAX_STAT) * 100}%` }} />
```
색이나 모양은 CSS 파일에 두고, **데이터에 따라 바뀌는 값만** `style`로 넣는다. 능력치 최댓값은 255라서 그 비율로 막대를 채운다.

### 객체를 돌면서 그리기
```jsx
{Object.entries(STAT_LABELS).map(([key, label]) => ( ... ))}
```
`Object.entries`는 `{ hp: 'HP', attack: '공격' }`을 `[['hp','HP'], ['attack','공격']]`로 바꿔 준다. `STAT_LABELS`에 적은 순서가 곧 화면 순서다.

## 개념 4: 계산 로직은 컴포넌트 밖으로

타입 상성 계산은 `src/lib/typeMatchup.js`에 있다.

```js
// 받는 피해 = 내 타입 각각이 받는 배율을 곱한 값
multipliers[attackType] = defenseTypes.reduce(
  (total, defenseType) => total * (TYPE_CHART[attackType][defenseType] ?? 1),
  1,
)
```
- 리자몽(불꽃/비행)이 바위 공격을 받으면: 불꽃이 바위에게 ×2, 비행도 바위에게 ×2 → **×4**
- 땅 공격은 비행이 ×0이라서, 곱하면 무조건 **×0**
- `reduce`는 배열을 돌면서 값을 하나로 모은다. 여기서는 1에서 시작해 차례로 곱한다.
- `?? 1`: 상성표에는 1배가 아닌 칸만 적어 뒀으니, 없는 칸은 1배다.

이 계산이 컴포넌트 안에 있었다면 테스트하려고 화면을 띄워야 했을 것이다. 순수 함수로 빼 두니 **리자몽, 이상해씨, 팬텀, 노말** 4가지 경우를 테스트 5개로 바로 검사할 수 있었다. 또 18×18 = 324칸 상성표는 사람이 옮겨 적다 보면 틀리기 쉬워서, PokeAPI의 공식 데이터와 한 칸씩 대조해서 324칸 모두 같다는 것도 확인했다.

## 접근성 한 가지

```jsx
<div role="tablist">
  <button role="tab" aria-selected={tab.id === active}>
```
`role`과 `aria-selected`는 화면을 보지 않고 듣는 사용자(스크린 리더)에게 "이건 탭이고, 지금 이게 선택됐다"고 알려 준다. 눈에 보이는 변화는 없다.

## 연습 거리

1. 팬텀(`/pokemon/94`)의 배틀 탭을 열어 ×0 줄에 노말과 격투가 있는지 보자. 고스트 타입이 왜 노말·격투 공격을 안 받는지 `typeChart.js`에서 찾아보자.
2. `BattleTab.css`의 `.stat__bar i` 배경색을 바꾸거나, 능력치가 100 이상이면 다른 색이 되게 만들어 보자. (힌트: `className={stats[key] >= 100 ? 'high' : ''}`)
3. `TABS` 배열의 순서를 바꿔서 탭 버튼 순서가 바뀌는지 확인하고 원래대로 돌려놓자.
