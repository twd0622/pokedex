# 10. 배포하기

## 이번 단계에서 한 일

- 도감을 인터넷에 올렸다: https://pokedex-sable-two-11.vercel.app/
- `vercel.json`을 추가해서 `/pokemon/25` 같은 주소에서 새로고침해도 404가 나지 않게 했다.
- `feature/pokedex`를 `main`에 합치고 GitHub(`twd0622/pokedex`)에 올렸다.
- Vercel을 GitHub 저장소에 연결했다. 이제 `main`에 push하면 자동으로 다시 배포된다.

## 개념 1: 배포 = `dist/`를 남의 컴퓨터에 올려 두기

```
npm run dev     개발 서버. 내 컴퓨터가 켜져 있을 때만, 나만 본다
npm run build   dist/ 폴더에 HTML·CSS·JS 파일을 만든다
                → 이 파일들을 아무 서버에 올리면 누구나 볼 수 있다
```
- `dist/index.html`, `dist/assets/index-B_uai9n6.js`, `dist/assets/index-CIGcE3V9.css`, 이 세 파일이 도감 전부다.
- 이 앱에는 우리가 만든 서버가 없다. 포켓몬 데이터는 브라우저가 PokeAPI에 직접 요청한다. 그래서 파일만 올려 두면 되는 **정적 사이트**다.
- 파일 이름의 `B_uai9n6` 같은 부분은 내용으로 만든 **해시**다. 내용이 같으면 이름도 같다. 배포된 파일 이름이 로컬 빌드와 같아서, 같은 코드가 올라갔다는 걸 확인할 수 있었다.

## 개념 2: 새로고침하면 404가 나는 이유

`src/main.jsx`에서 `BrowserRouter`를 쓴다. 주소가 `/pokemon/25`처럼 깔끔한 대신 문제가 하나 있다.

```
앱 안에서 카드 클릭
  → React Router가 주소만 바꾸고 화면을 다시 그린다. 서버에 묻지 않는다 ✅

/pokemon/25에서 새로고침 (또는 링크를 받아 바로 열기)
  → 브라우저가 서버에 "/pokemon/25 파일 주세요"라고 요청한다
  → dist/ 안에 그런 파일은 없다 → 404 ❌
```

`vercel.json`
```json
{
  "rewrites": [{ "source": "/(.*)", "destination": "/index.html" }]
}
```
- "어떤 주소로 요청이 와도 `index.html`을 보내라"는 뜻이다.
- `index.html`이 JS를 불러오고, React Router가 주소를 보고 `DetailPage`를 그린다.
- 없는 주소(`/does-not-exist`)도 서버는 200으로 응답한다. 「포켓몬을 찾을 수 없어요」는 앱의 `path="*"` 라우트(04)가 보여 준다.
- `dist/assets/...` 같은 실제 파일은 rewrite보다 먼저 찾아지므로 그대로 내려간다.

## 개념 3: Git 원격 저장소와 push

```
git remote add origin https://github.com/twd0622/pokedex.git   GitHub 저장소를 'origin'이라는 이름으로 등록
git push -u origin main                                        main을 origin에 올린다
```
- `-u`는 로컬 `main`과 `origin/main`을 짝지어 둔다. 다음부터는 `git push`만 쳐도 된다.
- GitHub는 비밀번호로 하는 push를 받지 않는다. Windows Git에 들어 있는 **Git Credential Manager**가 브라우저 로그인을 띄우고, 받은 토큰을 저장해 둔다.

`main`에 합칠 때는 **fast-forward**가 됐다. `main`에는 설계 문서 커밋 하나뿐이었고, `feature/pokedex`가 그 위에서 시작했다. 그래서 `main`의 이름표를 앞으로 옮기기만 하면 됐고, 병합 커밋이 따로 생기지 않았다.

```
전:  main ─ 95ed7f1
                └─ … 13개 … ─ 42e7eac  ← feature/pokedex
후:  95ed7f1 ─ … 13개 … ─ 42e7eac      ← main, feature/pokedex
```

## 개념 4: 자동 배포

```
코드 수정 → git commit → git push
  → GitHub가 Vercel에 "새 커밋 왔어"라고 알린다
  → Vercel 서버가 npm install → npm run build
  → 새 dist/로 사이트 교체 (1분 안팎)
```
- `dist/`는 `.gitignore`에 있어서 GitHub에 올라가지 않는다. 빌드는 Vercel이 한다.
- `main`이 아닌 브랜치를 push하면 **미리보기 배포**가 따로 생긴다. 실제 사이트를 건드리지 않고 새 기능을 확인할 수 있다.
