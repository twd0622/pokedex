# 00. 개발 환경과 프로젝트 뼈대

4. **Vitest**로 첫 테스트를 붙였다.

## 개념 정리

### Node.js와 npm
- **Node.js**는 브라우저 밖에서 JavaScript를 실행하는 프로그램이다. 우리가 만드는 도감은 브라우저에서 돌아가지만, 개발 도구(Vite, Vitest)는 Node.js 위에서 돌아간다.
- **npm**은 Node.js와 함께 설치되는 패키지 관리자다. 다른 사람이 만든 라이브러리를 내려받는다.
  - `package.json`: 이 프로젝트가 어떤 패키지를 쓰는지, 어떤 명령이 있는지 적어 둔 파일
  - `node_modules/`: 실제로 내려받은 패키지가 들어가는 폴더 (git에 올리지 않는다)
  - `npm install`: `package.json`을 보고 필요한 패키지를 전부 설치한다

### Vite
React 코드(JSX)는 브라우저가 그대로 이해하지 못한다. **Vite**가 중간에서 바꿔 주고, 파일을 저장하면 브라우저를 바로 갱신해 준다(HMR, Hot Module Replacement).

### 자주 쓸 명령

| 명령 | 하는 일 |
|---|---|
| `npm run dev` | 개발 서버 실행 → http://localhost:5173 |
| `npm test` | Vitest로 테스트 실행 |
| `npm run build` | 배포용 파일을 `dist/`에 만든다 |

## 코드가 실행되는 순서

```
index.html            ← 브라우저가 처음 여는 파일. <div id="root">가 있다
  └ src/main.jsx      ← React를 #root에 붙인다
      └ src/App.jsx   ← 실제 화면을 그리는 컴포넌트
```

`src/main.jsx`:
```jsx
createRoot(document.getElementById('root')).render(
  <StrictMode>
    <App />
  </StrictMode>,
)
```
- `createRoot(...)`: "이 div 안을 React가 관리한다"는 뜻이다.
- `<App />`: App 컴포넌트를 그린다. 컴포넌트는 다음 단계에서 자세히 다룬다.
- `<StrictMode>`: 개발 중에만 실수를 잡아 주는 검사 모드다. 개발 중에는 일부 코드가 일부러 두 번 실행되니 놀라지 말자.

## 폴더 구조 (앞으로 채워 갈 모습)

```
src/
  api/         PokeAPI에 요청하는 코드
  lib/         API 데이터를 화면용으로 바꾸는 순수 함수 (테스트 대상)
  data/        한국어 타입 이름처럼 고정된 데이터
  hooks/       데이터 불러오기 같은 재사용 로직
  components/  카드, 사이드바 같은 화면 부품
  pages/       목록 화면, 상세 화면
```

## 첫 테스트

`src/lib/format.js`
```js
export function formatNumber(id) {
  return '#' + String(id).padStart(4, '0')
}
```
`src/lib/format.test.js`
```js
it('4자리로 0을 채운다', () => {
  expect(formatNumber(6)).toBe('#0006')
})
```
- `export`: 다른 파일에서 `import`로 가져다 쓸 수 있게 내보낸다.
- `expect(실제값).toBe(기대값)`: 둘이 같아야 테스트가 통과한다.
- 이 프로젝트는 **테스트를 먼저 쓰고 실패하는 걸 확인한 다음** 기능을 만든다. 테스트가 정말 그 기능을 검사하는지 확인하는 방법이다.
