# 06. 진화·모습 탭: 트리 데이터와 상태 공유

## 이번 단계에서 한 일

- **진화 단계**: 파이리 → 리자드(Lv.16) → 리자몽(Lv.36)처럼 화살표와 조건으로 잇는다. 이브이처럼 갈래가 많으면 같은 단계에 여러 마리를 쌓는다. 누르면 그 포켓몬 상세로 간다.
- **모습 바꾸기**: 메가진화, 거다이맥스, 지역 모습 카드. 누르면 **위쪽 그림·타입·키·몸무게와 배틀 탭이 함께** 그 모습으로 바뀐다.
- 진화 단계를 따라 여러 포켓몬을 건너가도 「← 도감으로 돌아가기」는 목록으로 한 번에 돌아간다.

## 개념 1: 상태를 부모에 두고 여러 자식이 함께 쓰기

모습 카드는 「진화·모습」 탭 안에 있지만, 고른 모습은 **위쪽 Hero와 배틀 탭**도 써야 한다. 그래서 선택 상태를 셋의 공통 부모인 `DetailPage`에 둔다.

```
DetailPage (formIndex)
├─ Hero          form = forms[formIndex]   ← 그림, 타입이 바뀜
├─ BattleTab     form = forms[formIndex]   ← 능력치, 상성이 바뀜
└─ EvolutionTab  selectedFormIndex, onSelectForm   ← 카드를 누르면 바꿈
```

4단계의 사이드바와 같은 "상태 끌어올리기"다. 차이는 **값을 쓰는 곳이 셋**이라는 점이다. 값이 한곳에만 있으니 셋이 절대 어긋나지 않는다.

`BattleTab`은 이 단계에서 **한 줄도 고치지 않았다.** 처음부터 `form`을 props로 받게 만들어 두었기 때문에, 부모가 다른 모습을 넘기기만 하면 된다. 컴포넌트가 "어디서 왔는지 모르는 데이터"를 받아 그리기만 하면 재사용하기 쉽다.

## 개념 2: 다른 포켓몬으로 가면 선택을 초기화하기 (effect 없이)

메가리자몽X를 고른 채로 진화 단계의 파이리를 누르면, 파이리 페이지에서는 기본 모습이어야 한다. 흔히 이렇게 쓰고 싶어진다.

```js
// ❌ 이렇게 하지 않았다
useEffect(() => { setFormIndex(0) }, [id])
```
이렇게 하면 "파이리를 메가리자몽X 번호로 한 번 그림 → effect → 0으로 다시 그림"이 되어 잠깐 엉뚱한 화면이 보일 수 있다.

대신 **어느 포켓몬에서 고른 선택인지**를 함께 기억했다.
```js
const [formChoice, setFormChoice] = useState({ id, index: 0 })
const formIndex = formChoice.id === id ? formChoice.index : 0
```
지금 페이지의 `id`와 선택할 때의 `id`가 다르면 계산 결과가 그냥 0이 된다. 3단계부터 계속 나온 원칙이다. **계산으로 얻을 수 있으면 effect로 맞추지 않는다.**

## 개념 3: 트리 모양 데이터를 단계로 묶기

API는 진화 계열을 이런 목록으로 준다.
```
이브이    evolves_from: null
샤미드    evolves_from: 133 (이브이)
쥬피썬더  evolves_from: 133
...
```
"누구에게서 진화했는지"만 있는 **트리** 구조다. 화면에는 단계별로 그려야 해서 `buildEvolutionStages`로 바꾼다.

```js
const stage = parentId === null ? 0 : stageOf[parentId] + 1
stageOf[species.id] = stage
stages[stage] ??= []      // 그 단계 배열이 없으면 빈 배열로 만든다
stages[stage].push(...)
```
부모의 단계 + 1이 내 단계다. API가 진화 순서대로 정렬해 주니 부모가 항상 먼저 나와서, 한 번 훑는 것으로 끝난다.

### 진화 조건을 글로
`formatEvolutionCondition`은 조건 조각을 모아 `' + '`로 잇는다.

| API | 화면 |
|---|---|
| `min_level: 16` | Lv.16 |
| `use-item` + 불꽃의돌 | 불꽃의돌 사용 |
| `trade` | 통신교환 |
| `min_happiness: 160` + `time_of_day: 'night'` | 친밀도 160 이상 (밤) |
| 알 수 없음 (특정 장소 등) | 특수 조건 |

리피아는 게임마다 진화 방법이 달라서 API에 방법이 6개나 적혀 있다. 대부분 "특정 장소에서 레벨업"이라 우리가 받는 정보로는 「특수 조건」이 된다. 그래서 **알아볼 수 있는 첫 번째 조건**(리프의돌 사용)을 고르게 했다. 이 경우도 테스트가 지킨다.

## 개념 4: Fragment와 key

```jsx
{stages.map((stage, index) => (
  <Fragment key={index}>
    {index > 0 && <div className="evolution__arrow">→</div>}
    <div className="evolution__stage">...</div>
  </Fragment>
))}
```
`map` 한 번에 화살표와 단계 **두 개**를 돌려주고 싶을 때, 감싸는 div 없이 묶는 것이 `Fragment`다. (`<>...</>`도 Fragment지만 `key`를 붙이려면 이름을 써야 한다.) 단계 순서는 바뀌지 않아서 여기서는 index를 key로 써도 괜찮다.

## 개념 5: Link state로 「돌아가기」 깊이 세기

5단계에서 카드 링크에 `fromList` 쪽지를 실었다. 이번에는 `depth`를 더했다.
```js
// 카드: depth 1
state={{ fromList: location.search, depth: 1 }}
// 진화 단계 링크: 지금 depth + 1
depth: (location.state.depth ?? 1) + 1
// 돌아가기
navigate(-(location.state.depth ?? 1))
```
목록 → 리자몽 → 파이리 → 리자드로 갔다면 depth는 3이다. 「돌아가기」는 `navigate(-3)`, 즉 뒤로 3번 가서 목록에 도착한다. 탭 전환은 `replace`라서 방문 기록이 늘지 않으니 숫자가 정확하다.
