# 04. 라우팅과 상세 페이지

## 이번 단계에서 한 일

- **React Router**로 주소마다 다른 화면을 보여 준다.
  - `/` → 목록, `/pokemon/6` → 리자몽 상세, 그 밖의 주소 → 「포켓몬을 찾을 수 없어요」
- 카드를 누르면 상세 페이지로 간다. 지금은 위쪽 영역(그림, 이름, 분류, 타입, 키·몸무게, 도감 설명)까지 만들었다.
- 목록의 검색어와 필터를 **주소**(`?q=리자&gen=1&type=fire`)로 옮겼다. 상세 페이지에 갔다 돌아와도, 새로고침해도 조건이 그대로 남는다.
- 데이터 불러오기를 어디서나 쓸 수 있는 **`useAsync` 훅**으로 만들었다.

## 개념 1: 라우팅 — 주소 → 화면

`src/main.jsx`
```jsx
<BrowserRouter>
  <App />
</BrowserRouter>
```
`BrowserRouter`는 브라우저 주소창을 지켜보다가 주소가 바뀌면 알려 준다. 앱 전체를 감싸야 그 안에서 라우터 기능을 쓸 수 있다.

`src/App.jsx`
```jsx
<Routes>
  <Route path="/" element={<ListPage />} />
  <Route path="/pokemon/:id" element={<DetailPage />} />
  <Route path="*" element={<NotFound />} />
</Routes>
```
- `Routes`는 지금 주소와 맞는 `Route` **하나**를 골라 그 `element`를 그린다.
- `:id`는 **자리 표시자**다. `/pokemon/6`이면 `id`는 `'6'`이 된다.
- `*`는 "나머지 전부"다.

이렇게 페이지를 새로 받지 않고 JavaScript로 화면만 바꾸는 앱을 **SPA**(Single Page Application)라고 한다. 그래서 상세 페이지에 갔다 와도 목록 데이터를 다시 받지 않는다.

## 개념 2: Link와 useParams

```jsx
<Link to={`/pokemon/${pokemon.id}`}>...</Link>
```
`<a href>`를 쓰면 페이지 전체를 새로 받는다. `<Link>`는 주소만 바꾸고 React가 화면을 갈아 끼운다.

```jsx
const params = useParams()          // { id: '6' }
const id = parsePokemonId(params.id) // 6, 이상한 값이면 null
```
주소에서 꺼낸 값은 **항상 문자열**이고, 사용자가 아무 글자나 칠 수 있다. 그래서 `parsePokemonId`로 1~1025 사이 정수인지 검사한다. (`/pokemon/abc`, `/pokemon/99999`를 직접 쳐 보자)

## 개념 3: 상태를 주소에 두기 — useSearchParams

지난 단계에서는 검색어를 `useState`로 가지고 있었다. 그런데 상세 페이지로 가면 `ListPage`가 화면에서 사라지면서 **state도 같이 사라진다.** 돌아오면 처음부터 다시 시작한다.

그래서 검색어와 필터를 주소 쿼리에 옮겼다.
```js
const [searchParams, setSearchParams] = useSearchParams()
const query = searchParams.get('q') ?? ''
```
- 주소는 페이지를 오가도, 새로고침해도 남는다. 주소를 복사해 두면 같은 조건을 다시 열 수도 있다.
- 사용법은 `useState`와 비슷하다. 읽고(`get`), 바꾼다(`setSearchParams`).
- `{ replace: true }`: 글자를 칠 때마다 방문 기록이 쌓이면 「뒤로」를 수십 번 눌러야 한다. 그래서 현재 기록을 덮어쓴다.
- 주소 값은 사용자가 마음대로 바꿀 수 있으니, `type=abc`처럼 없는 타입이면 「전체」로 친다.

**어디에 상태를 둘까?** 화면을 떠나도 남아야 하거나 공유할 만한 값이면 주소에 둔다. 잠깐 쓰고 마는 값(예: 메뉴가 열렸는지)은 `useState`에 둔다.

### 「돌아가기」가 스크롤 위치까지 지키는 방법
```jsx
<Link to={`/pokemon/${id}`} state={{ fromList: location.search }}>
```
카드 링크에 **state**를 실어 보낸다. 주소에는 안 보이는 쪽지 같은 것이다. 상세 페이지는 이 쪽지가 있으면 "목록에서 왔구나" 하고 `navigate(-1)`(브라우저 뒤로)을 쓴다. 뒤로 가면 브라우저가 스크롤 위치도 되돌려 준다. 주소를 직접 열어서 쪽지가 없으면 `/`로 간다.

## 개념 4: useAsync — 불러오기 로직 재사용

```js
const { data: detail, loading, error, retry } = useAsync(() => loadDetail(id), [id])
```
- 지난 단계의 `usePokemonList`는 목록 전용이었다. 상세, 기술, 출현 장소도 똑같이 "불러오기 + 로딩 + 오류 + 다시 시도"가 필요해서 **함수를 인자로 받는 훅**으로 일반화했다.
- 두 번째 인자 `[id]`가 바뀌면 다시 불러온다. 리자몽 → 파이리로 이동하면 `id`가 바뀌니 자동으로 파이리를 불러온다.

### 경쟁 상태(race condition) 막기
리자몽 페이지에서 요청을 보내고, 응답이 오기 전에 파이리로 이동했다고 하자. 리자몽 응답이 **늦게** 오면 파이리 페이지에 리자몽이 그려질 수 있다.

```js
useEffect(() => {
  let ignore = false
  asyncFn().then((data) => {
    if (!ignore) setResult({ key, data, error: null })
  })
  return () => { ignore = true }   // id가 바뀌면 이전 effect를 정리
}, [key])
```
`id`가 바뀌면 React는 **이전 effect의 정리 함수를 먼저 실행한다.** 그래서 리자몽 요청의 `ignore`가 `true`가 되고, 늦게 온 리자몽 응답은 버려진다.

### loading을 state로 두지 않은 이유
```js
const loading = result.key !== key
```
결과마다 "어떤 요청의 결과인지"를 `key`로 붙여 두고, **지금 요청의 결과가 아직 없으면 로딩 중**이라고 계산한다. 지난 단계에서 배운 "계산할 수 있으면 state로 두지 않는다"를 그대로 적용했다. 덕분에 effect 안에서 `setLoading(true)`를 부를 필요가 없다.

## 개념 5: 훅은 조건문보다 먼저

```jsx
function DetailPage() {
  const id = parsePokemonId(params.id)
  const { ... } = useAsync(...)     // ← 훅을 먼저 다 부르고

  if (id === null) return <NotFound />   // ← 그다음에 조건별로 return
  if (loading) return <p>불러오는 중…</p>
  ...
}
```
React는 훅을 **부른 순서**로 각 훅의 상태를 구분한다. `if`문 뒤에서 훅을 부르면 렌더링마다 순서가 달라질 수 있어서 규칙 위반이다.

## API 데이터 정리 (normalizeDetail)

PokeAPI의 단위와 표기를 화면에 맞게 바꾼다. 테스트 13개가 지키고 있다.

| API 값 | 화면 값 | 이유 |
|---|---|---|
| `height: 17` | `1.7m` | 단위가 데시미터(dm) |
| `weight: 905` | `90.5kg` | 단위가 헥토그램(hg) |
| `gender_rate: 1` | 암컷 12.5% | 8분의 몇이 암컷인지. -1은 성별 없음 |
| `hatch_counter: 20` | 5,140걸음 | 1사이클 = 257걸음 |
| `'medium-slow'` | 중간 느림 | API에 한국어 번역이 없어서 `data/labels.js`에 고정 |
| `'지상 1400m까지\n날개를…'` | 줄바꿈 없는 한 줄 | 게임 화면용 줄바꿈 문자 제거 |

## 연습 거리

1. 「1세대 + 불꽃」을 고르고 아래로 스크롤해서 리자몽을 누른 뒤, 「← 도감으로 돌아가기」를 눌러 보자. 필터와 스크롤 위치가 그대로인지 확인한다.
2. 주소창에 `/pokemon/150`(뮤츠)을 직접 쳐 보자. 「전설」 배지가 보인다. 이번에는 「돌아가기」가 목록 첫 화면으로 간다. 왜 그런지 `BackLink` 코드를 보고 설명해 보자.
3. 주소창에 `/?type=dragon&gen=4`를 쳐 보자. 사이드바가 그 값으로 선택되어 있다. `type=abc`로 바꾸면 어떻게 되는지도 보자.
