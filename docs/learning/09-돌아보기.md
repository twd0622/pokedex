# 09. 돌아보기

## 완성된 도감의 지도

```
main.jsx ── BrowserRouter
  └ App ── Routes
      ├ "/"             ListPage           검색어·세대·타입 = 주소 쿼리 (?q=&gen=&type=)
      │   ├ Header + 검색창
      │   ├ Sidebar
      │   └ PokemonGrid → PokemonCard → TypeBadge
      │
      ├ "/pokemon/:id"  DetailPage         탭 = 주소 쿼리 (?tab=), 선택한 모습 = state
      │   ├ BackLink
      │   ├ Hero
      │   ├ Tabs
      │   └ BattleTab | EvolutionTab | MovesTab | DetailsTab
      │
      └ "*"             NotFound
```

## 데이터가 흐르는 길

```
PokeAPI (GraphQL)
   │  src/api/        요청만 담당. 응답 그대로 돌려줌
   ▼
src/lib/              순수 함수로 화면용 모양으로 바꿈 ← 테스트 62개가 여기를 지킴
   │  normalizeList, normalizeDetail, filterPokemon, getDefensiveMultipliers,
   │  buildEvolutionStages, toVersionGroupOptions, normalizeMoves, groupEncounters
   ▼
src/hooks/            언제 요청할지, 로딩·오류 상태 관리
   │  usePokemonList, useAsync
   ▼
src/components/       받은 데이터를 그리기만 함
```

이렇게 층을 나눈 덕분에 생긴 일들:
- PokeAPI 응답 모양이 바뀌면 `api/`와 `lib/`만 고치면 된다.
- 상성 계산, 필터, 진화 단계처럼 틀리기 쉬운 로직은 브라우저 없이 테스트로 확인했다.
- `BattleTab`은 6단계에서 만든 뒤 한 번도 고치지 않았는데, 7단계에서 모습 바꾸기와 바로 맞물렸다.

## 배운 React 개념

| 개념 | 처음 나온 곳 | 한 줄 요약 |
|---|---|---|
| 컴포넌트, JSX | 01 | 화면 조각을 돌려주는 함수 |
| props, children | 01 | 부모 → 자식으로 값 전달. 읽기 전용 |
| map과 key | 01 | 배열 → 컴포넌트 목록. key는 이름표 |
| useState | 02 | React가 기억하는 값. set 함수로만 바꾼다 |
| useEffect와 정리 함수 | 02 | 그린 뒤에 하는 바깥 작업. 늦게 온 응답은 버린다 |
| 커스텀 훅 | 02, 04 | 상태 로직을 함수로 떼어 내 재사용 |
| 제어 컴포넌트 | 03, 07 | 입력창·select의 값을 state가 쥔다 |
| 상태 끌어올리기 | 03, 06 | 여럿이 쓰는 값은 공통 부모에 |
| 파생 데이터, useMemo | 03 | 계산할 수 있는 건 state로 두지 않는다 |
| 라우팅, useParams | 04 | 주소 → 화면 |
| 주소에 상태 두기 | 04, 05 | 새로고침·페이지 이동 후에도 남아야 하는 값 |
| Link state | 04, 06 | 주소에 안 보이는 쪽지 (돌아가기 깊이) |
| 조건부 렌더링 | 05 | `&&`, 삼항, 이른 return |
| Fragment | 06 | 감싸는 태그 없이 여러 요소 묶기 |
| 마운트·언마운트 | 07 | 조건부로 그리면 필요할 때만 불러온다 |

## 여러 번 나온 원칙 세 가지

1. **계산할 수 있으면 state로 두지 않는다.** 걸러진 목록(03), 로딩 상태(04), 선택 초기화(06), 기본 버전(07)이 모두 이 원칙이었다.
2. **effect는 바깥 세상과 맞추는 데만 쓴다.** 사용자 행동에 따른 변경은 이벤트 처리 함수에서 한다(02).
3. **가정은 실제 데이터로 확인한다.** "번호가 크면 최신"은 틀렸다(07, 08). 리피아의 진화 방법은 6개였다(06). 상성표 324칸은 공식 데이터와 대조했다(05).

## 남겨 둔 작은 한계

- 배루키 계열처럼 "공격과 방어 능력치 비교" 같은 진화 조건은 표시하지 않는다(모두 Lv.20으로 보임).
- 일부 출현 장소와 만남 방법은 PokeAPI에 한국어 번역이 없어서 영어로 보인다.
- 기술·출현 장소 탭은 다시 열 때마다 새로 불러온다.

## 다음에 해 볼 만한 것

- **TypeScript**: `PokemonSummary`, `FormDetail` 같은 데이터 모양을 타입으로 적으면, 이름을 잘못 쓰는 실수를 편집기가 바로 잡아 준다.
- **React Query (TanStack Query)**: `useAsync`가 하던 일에 캐시, 재시도, 미리 불러오기를 더해 준다. 직접 만들어 봤으니 무엇을 대신해 주는지 바로 보일 것이다.
- **컴포넌트 테스트 (React Testing Library)**: 지금은 `lib/`만 테스트했다. "검색창에 '리자'를 치면 카드 4장" 같은 화면 테스트도 써 볼 수 있다.
- **배포**: `npm run build`로 만든 `dist/`를 Netlify나 GitHub Pages에 올리면 휴대폰에서도 볼 수 있다. 주소 기반 라우팅이라 "없는 경로도 index.html로" 설정이 필요하다.
- **즐겨찾기**: localStorage에 좋아하는 포켓몬 번호를 저장하고 사이드바에 「즐겨찾기」 필터를 추가해 보자. 지금까지 배운 것만으로 만들 수 있다.
