# 08. 세부 데이터 탭: 데이터 묶기와 표

## 이번 단계에서 한 일

- **세부 데이터**: 성비, 포획률, 알 그룹, 부화 걸음 수, 성장 속도, 서식지, 색깔을 칸으로 보여 준다.
- **출현 장소**: 게임 버전을 고르면 그 버전에서 야생으로 만나는 장소와 방법이 표로 나온다. 「전체」를 고르면 버전별 묶음 표를 전부 보여 준다.
- 기본 버전은 **기록이 있는 가장 최신 버전**이다.

## 개념 1: 배열 데이터로 반복되는 화면 만들기

```js
const facts = [
  ['성비', genderText(detail.genderFemalePercent)],
  ['포획률', detail.captureRate],
  ...
]

{facts.map(([label, value]) => (
  <div key={label} className="facts__item">
    <dt>{label}</dt>
    <dd>{value}</dd>
  </div>
))}
```
일곱 칸의 모양이 똑같으니 **데이터 배열 + `map`** 한 번으로 그린다. 칸을 하나 더 넣고 싶으면 배열에 한 줄만 추가하면 된다. 2단계부터 계속 쓴 패턴이다.

## 개념 2: 묶기(group by)

API는 출현 기록을 한 줄씩 길게 준다. 피카츄만 해도 180줄이 넘는다.
```
레드     상록숲          풀숲
레드     상록숲          풀숲   ← 레벨만 다른 같은 기록
레드     무인발전소      풀숲
블루     상록숲          풀숲
...
```
화면에서는 **버전별로 묶고, 같은 (장소, 방법)은 하나로 합쳐야** 한다. `groupEncounters`가 그 일을 한다.

```js
const groups = new Map()
for (const row of rows) {
  if (!groups.has(version.id)) groups.set(version.id, { ..., places: [], seen: new Set() })
  const group = groups.get(version.id)
  const key = `${place.location}|${place.method}`
  if (group.seen.has(key)) continue   // 이미 넣은 조합이면 건너뛴다
  group.seen.add(key)
  group.places.push(place)
}
```
- **`Map`**: 키 → 값 저장소다. "이 버전의 묶음이 이미 있나?"를 빠르게 확인한다.
- **`Set`**: 중복 없는 값 모음이다. "이 (장소, 방법)을 이미 넣었나?"를 확인한다.
- 마지막에 `[...groups.values()]`로 배열로 바꿔서 정렬한다.

7단계의 `toVersionGroupOptions`도 같은 구조다. 데이터를 화면에 맞게 묶는 일은 아주 자주 나온다.

## 개념 3: 대체 문구 처리

API 데이터는 늘 빈칸이 있을 수 있다고 생각하자.

| 상황 | 화면 |
|---|---|
| 성별 없는 포켓몬 (`gender_rate: -1`) | 성별 없음 |
| 서식지 정보 없음 | 정보 없음 |
| 한국어 장소 이름 없음 | 영어 이름을 보기 좋게 (`trophy-garden` → Trophy Garden) |
| 모르는 만남 방법 | 영어 그대로 (예: honey-tree) |
| 출현 기록이 하나도 없음 | 야생에서 만나는 기록이 없어요 |

`??` 연산자로 "없으면 이것"을 짧게 쓴다.
```js
location: location.locationnames[0]?.name ?? toTitle(location.name)
```
`?.`는 "앞이 없으면 에러 내지 말고 undefined"라는 뜻이다. `locationnames`가 빈 배열이면 `[0]`은 undefined이고, `.name`에서 에러가 나는 대신 undefined가 된다. 그러면 `??` 뒤의 영어 이름을 쓴다.

## 개념 4: 「전체」 같은 특별한 선택값

```js
const ALL = 'all'
<option value={ALL}>전체</option>
```
버전 id는 숫자인데 「전체」는 그렇지 않다. 그래서 문자열 상수 `ALL`로 구분하고, 나머지 값만 `Number(...)`로 바꾼다. 상수로 이름을 붙여 두면 오타(`'al'`)로 생기는 버그도 막을 수 있다.

## 또 만난 "번호 ≠ 출시 순서"

7단계와 같은 문제가 출현 기록에도 있었다. 버전 번호 대신 버전 그룹의 `order`로 정렬했다. 한 번 배운 교훈은 비슷한 곳에 다시 쓰자.

참고: 다이아몬드·펄·플래티넘이 「디아루가·펄기아·기라티나」로 나오는 건 오류가 아니다. 한국에서 실제로 그 이름으로 출시됐다.
