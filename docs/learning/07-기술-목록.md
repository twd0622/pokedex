# 07. 기술 탭: 필요할 때 불러오기, select 메뉴, 기본값 계산

## 이번 단계에서 한 일

- 「기술」 탭에서 **게임 버전**과 **배우는 방법**(레벨업 / 기술머신 / 알 기술 / 가르침)을 골라 기술 표를 본다.
- 표: 레벨(레벨업일 때만, 0은 「진화 시」), 기술 이름, 타입, 위력, 명중. 값이 없으면 「—」
- 기본값은 **레벨업 기술이 있는 가장 최신 버전**이다. 리자몽이면 스칼렛·바이올렛이다.
- 모습을 바꾸면(예: 메가리자몽X) 그 모습의 기술로 다시 불러온다.

```
MovesTab (pokemonId)
 ├ useAsync → fetchMoveVersionGroups   어떤 버전·방법이 있나 (요청 1)
 ├ <select> 버전, <select> 방법
 └ MoveTable (pokemonId, versionGroupId, method)
     └ useAsync → fetchMoves            그 조합의 기술 목록 (요청 2)
```

## 개념 1: 탭을 열 때만 불러오기

```jsx
{activeTab === 'moves' && <MovesTab pokemonId={form.pokemonId} />}
```
`MovesTab`은 기술 탭을 골랐을 때만 화면에 나오고(**마운트**), 그때 안의 `useAsync`가 처음 실행된다. 기술 데이터는 양이 많아서(리자몽은 전 버전 합쳐 1,500줄쯤) 상세 페이지를 열 때마다 받으면 낭비다. **컴포넌트를 조건부로 그리는 것만으로** "필요할 때 불러오기"가 된다.

다른 탭으로 가면 `MovesTab`이 사라지고(**언마운트**) 안의 state도 사라진다. 그래서 다시 열면 다시 불러온다. 지금은 이걸로 충분하지만, 한 번 받은 데이터를 기억해 두고 싶다면 나중에 React Query 같은 도구를 배우면 된다.

## 개념 2: 의존성이 여러 개인 요청

```js
useAsync(
  () => fetchMoves(pokemonId, versionGroupId, method),
  [pokemonId, versionGroupId, method],
)
```
셋 중 **하나라도 바뀌면** 다시 요청한다. 버전 메뉴를 바꾸면 `versionGroupId`가 바뀌고, 모습을 바꾸면 `pokemonId`가 바뀐다. 요청을 다시 보내는 코드를 따로 쓸 필요가 없다. 의존성 배열에 "이 값으로 요청한다"고 적어 두기만 하면 된다.

메뉴를 빠르게 여러 번 바꿔도 5단계에서 만든 `ignore` 처리 덕분에 **마지막으로 고른 조합의 결과만** 화면에 남는다.

## 개념 3: `<select>`도 제어 컴포넌트

```jsx
<select value={method} onChange={(event) => choose({ method: event.target.value })}>
  {version.methods.map((m) => (
    <option key={m} value={m}>{LEARN_METHODS[m]}</option>
  ))}
</select>
```
3단계의 검색창과 똑같다. `value`는 state에서, 바꾸면 `onChange`로 state를 고친다.

**주의:** `<select>`의 값은 항상 **문자열**이다. 버전 id는 숫자라서 `Number(event.target.value)`로 바꿔서 저장했다. 안 바꾸면 `25 === '25'`가 `false`라서 선택한 버전을 찾지 못한다.

## 개념 4: "사용자가 고른 값"과 "기본값"을 나눠 생각하기

```js
const [choice, setChoice] = useState({ pokemonId: null, versionGroupId: null, method: null })

const defaultVersion = options.find((o) => o.methods.includes('level-up')) ?? options[0]
const chosenVersion = choice.pokemonId === pokemonId
  ? options.find((o) => o.id === choice.versionGroupId)
  : undefined
const version = chosenVersion ?? defaultVersion
```
- state에는 **사용자가 실제로 고른 것만** 둔다. 처음에는 아무것도 안 골랐다(`null`).
- 화면에 쓸 값은 "고른 게 있고 지금도 유효하면 그것, 아니면 기본값"으로 **계산**한다.
- 모습을 바꿔서 `pokemonId`가 달라지면 예전 선택은 무시되고 기본값으로 돌아간다. 고른 버전이 새 모습에 없을 때도 마찬가지다.

이렇게 하면 "데이터가 도착하면 effect로 기본값을 state에 넣기" 같은 코드가 필요 없다. 6단계의 모습 선택과 같은 기법이다.

## 데이터에서 발견한 함정: 번호 ≠ 출시 순서

계획에서는 "버전 그룹 번호(id)가 크면 최신"이라고 가정했다. 실제 데이터를 보니 아니었다.

| id | 버전 | 출시 순서(order) |
|---|---|---|
| 32 | Pokémon Champions | 32 |
| 29 | 블루(일본판) | 3 근처 |
| 28 | 레드·그린(일본판) | 1 근처 |
| 25 | 스칼렛·바이올렛 | 27 |

일본판 1세대가 나중에 데이터에 추가되면서 큰 번호를 받았다. 그래서 **`order` 필드로 정렬**하게 바꿨다. 또 Champions의 기술은 「train」이라는 특별한 방식뿐이라, 우리가 보여 주는 4가지 방법이 없는 버전은 메뉴에서 뺐다. **가정은 실제 데이터로 확인하자.** 테스트에도 이 경우를 넣었다.

## 정렬: `localeCompare`

```js
a.name.localeCompare(b.name, 'ko')
```
한글을 가나다순으로 비교한다. 레벨업은 레벨 순서로 정렬하고, 레벨이 같으면 이름순이다(`a.level - b.level || ...`). 레벨 차이가 0이면 `||` 뒤의 이름 비교로 넘어간다.
